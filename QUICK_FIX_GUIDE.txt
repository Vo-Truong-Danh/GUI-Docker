YOUR ERROR:
  DiskPart has encountered an error: The process cannot access the file 
  because it is being used by another process.

WHAT HAPPENED:
  Docker processes were still running and had the VHDX file locked.
  The 10-second wait in the old script wasn't enough.

═══════════════════════════════════════════════════════════════════════════

SOLUTION 1: Use v2.0 Automatic (RECOMMENDED)
═══════════════════════════════════════════════════════════════════════════

  1. Run as Administrator: MAIN_MENU.bat
  2. Choose option 7 (COMPACT DOCKER DISK [v2.0])
  3. Press Y
  4. Wait 15-20 minutes
  5. Done!

  ✅ NEW: Automatically kills all Docker processes
  ✅ NEW: Verifies processes are stopped
  ✅ NEW: Auto-restarts Docker
  ✅ NEW: Shows space saved

SOLUTION 2: Manual Fix (if v2.0 fails)
═══════════════════════════════════════════════════════════════════════════

  Step 1: Kill Docker Processes
  ─────────────────────────────
  Option A - PowerShell:
    Get-Process | Where-Object {$_.ProcessName -like "*docker*"} | Stop-Process -Force

  Option B - Task Manager:
    1. Open Task Manager (Ctrl+Shift+Esc)
    2. Go to "Details" tab
    3. Kill these:
       - Docker Desktop.exe
       - com.docker.backend.exe
       - com.docker.service.exe
       - com.docker.vpnkit.exe
       - com.docker.proxy.exe

  Step 2: Shutdown WSL
  ────────────────────
    wsl --shutdown

  Step 3: Wait
  ────────────
    Wait 30 seconds (important!)

  Step 4: Run Manual Compact
  ──────────────────────────
    MANUAL_COMPACT_VHDX.bat

TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════

  Problem: v2.0 still fails with "file locked" error
  ───────────────────────────────────────────────────
  Solution:
    1. Reboot PC
    2. Don't start Docker Desktop
    3. Run MANUAL_COMPACT_VHDX.bat immediately

  Problem: Docker won't start after compaction
  ────────────────────────────────────────────
  Solution:
    1. Start Docker Desktop manually
    2. Wait for "Engine running"
    3. Run: docker-compose up -d

  Problem: HDFS data is gone
  ──────────────────────────
  Solution:
    This shouldn't happen if containers were running before compact.
    Check: docker exec namenode hdfs dfs -ls /input/data/
    If gone, you'll need to re-upload.
